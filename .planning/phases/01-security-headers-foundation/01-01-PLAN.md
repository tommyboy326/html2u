<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| viewer browser → wrapper route | Trusted-origin HTML the app controls; baseline headers protect the viewer's tab from clickjacking/MIME-sniff/referrer leakage |
| viewer browser → /s/<id>/raw (sandboxed iframe) | UNTRUSTED third-party HTML. The raw route's OWN strict CSP is the only thing standing between uploaded HTML and the viewer. Wrapper headers MUST NOT cross into here |
| config build → response headers | next.config.ts values become response headers verbatim; static strings, no request-derived interpolation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | next.config.ts `headers()` source/value | mitigate | Header keys/values are static literals — NO request data (no `:param` interpolation into header VALUES) is used, so header injection / response splitting via config is structurally impossible. Acceptance asserts exact literal values. |
| T-01-02 | Information Disclosure | wrapper header leak into /s/<id>/raw | mitigate | Negative-lookahead `source` excludes `/s/.*/raw`; acceptance REQUIRES `curl -I` of the raw route to show none of the wrapper headers and no X-Frame-Options. Breaking the iframe trust contract is the highest-severity failure mode for this phase — this is the blocking check. |
| T-01-03 | Spoofing/Elevation | Report-Only CSP assumed to enforce | accept (documented) | SEC-02b ships `Content-Security-Policy-Report-Only` which DOES NOT enforce — it cannot stop an XSS or inline-script attack on the wrapper. This is called out explicitly so no downstream phase assumes the wrapper is CSP-protected. Enforce mode is deferred to SEC-V3-05 (requires inline-theme nonce refactor). The raw route's own enforcing CSP is unaffected. |
| T-01-04 | Information Disclosure | Reporting-Endpoints URL points at not-yet-built endpoint | accept | `/api/csp-report` (SEC-03) does not exist this phase; reports 404 until then. No data leaks because nothing receives them yet; the URL is first-party. Documented in SUMMARY. |
</threat_model>
